An implementation for wallet transfers backed by PostgreSQL 16.

### Concurrency Design

1. **Deadlock Prevention via Strict Lock Ordering**:
   Concurrent transfers—especially between the same two accounts in opposite directions ($A \to B$ and $B \to A$) or cycles ($A \to B$, $B \to C$, $C \to A$)—can deadlock if locks are acquired in arbitrary order. To guarantee an acyclic lock dependency graph (Dijkstra's resource ordering), every transfer always acquires row-level locks (`SELECT ... FOR UPDATE`) in ascending order of `account.id` (`min(from_id, to_id)` followed by `max(from_id, to_id)`).

2. **Accurate Balance Verification**:
   Under PostgreSQL's default `READ COMMITTED` isolation level, `SELECT ... FOR UPDATE` waits if a row is currently locked by a concurrent transaction, and once unblocked, it locks and evaluates the newly committed version of the row. Checking the sender's balance under this exclusive row lock guarantees that balances never drop below zero and that transfers which fit concurrently always succeed.

3. **Fast Short-Circuiting**:
   If the sender has the lower ID (`from_id == min(from_id, to_id)`), we inspect the sender's balance immediately after the first query; if insufficient, the transaction rolls back and returns `False` without locking the receiver.

4. **Atomic Balance Update**:
   A single `UPDATE` with a `CASE` expression debits the sender and credits the receiver in a single round-trip, keeping database calls minimal (at most 5 calls per successful transfer, well below the 60-call limit).

```python
from psycopg import errors

RETRIABLE_EXCEPTIONS = tuple(
    exc
    for exc in (
        getattr(errors, "SerializationFailure", None),
        getattr(errors, "DeadlockDetected", None),
        getattr(errors, "LockNotAvailable", None),
        getattr(errors, "OperationalError", None),
    )
    if exc is not None
)


def transfer(db, from_id: int, to_id: int, amount: int) -> bool:
    first_id = min(from_id, to_id)
    second_id = max(from_id, to_id)

    for _ in range(8):
        try:
            db.begin()

            # Lock the lower-numbered account first
            r1 = db.execute(
                "SELECT balance FROM accounts WHERE id = %s FOR UPDATE",
                (first_id,),
            )

            if from_id == first_id:
                # Sender is first_id; check balance before locking second_id
                if r1[0][0] < amount:
                    db.rollback()
                    return False
                db.execute(
                    "SELECT balance FROM accounts WHERE id = %s FOR UPDATE",
                    (second_id,),
                )
            else:
                # Receiver is first_id; lock sender (second_id) and check balance
                r2 = db.execute(
                    "SELECT balance FROM accounts WHERE id = %s FOR UPDATE",
                    (second_id,),
                )
                if r2[0][0] < amount:
                    db.rollback()
                    return False

            # Transfer amount between accounts in a single statement
            db.execute(
                "UPDATE accounts SET balance = balance + CASE "
                "WHEN id = %s THEN %s ELSE %s END "
                "WHERE id IN (%s, %s)",
                (to_id, amount, -amount, from_id, to_id),
            )
            db.commit()
            return True

        except RETRIABLE_EXCEPTIONS:
            try:
                db.rollback()
            except Exception:
                pass
            continue

    return False
```
