The whole purchase is one SQL statement. A data-modifying CTE decrements stock only when enough remains and inserts the order from the rows that update returned. Because a single statement commits atomically, the stock change and the order row can't diverge. Under read committed, a concurrent UPDATE waits on the row lock and then rechecks `stock >= qty` against the new row version, so a purchase that fits is never refused because of a concurrent one. No retries or explicit transactions are needed, and each call makes one `db` call.

```python
def purchase(db, product_id: int, qty: int) -> bool:
    rows = db.execute(
        """
        WITH upd AS (
            UPDATE products
               SET stock = stock - %(qty)s
             WHERE id = %(product_id)s
               AND stock >= %(qty)s
         RETURNING id
        )
        INSERT INTO orders (product_id, qty)
        SELECT id, %(qty)s FROM upd
        RETURNING id
        """,
        {"product_id": product_id, "qty": qty},
    )
    return len(rows) == 1
```
