The approach is a unique index on `idempotency_key`, plus `INSERT ... ON CONFLICT DO NOTHING`. If the insert conflicts, the function reads the row that the other attempt committed. A bounded retry loop covers serialization failures and deadlocks.

```python
import psycopg
from psycopg import errors


def migrate(db) -> None:
    # Enforces rule 1 at the database level, so no two rows can share a key.
    db.execute(
        "CREATE UNIQUE INDEX IF NOT EXISTS payments_idempotency_key_uidx "
        "ON payments (idempotency_key)"
    )


def create_payment(db, idempotency_key: str, customer_id: int, amount: int) -> int:
    last_error = None
    # Bounded retries: at most 6 attempts, each using at most 4 db calls
    # (begin, insert, select, commit), plus one rollback per failure,
    # which stays well under the 60-call limit.
    for _ in range(6):
        try:
            db.begin()  # default isolation: read committed
            rows = db.execute(
                "INSERT INTO payments (idempotency_key, customer_id, amount) "
                "VALUES (%s, %s, %s) "
                "ON CONFLICT (idempotency_key) DO NOTHING "
                "RETURNING id",
                (idempotency_key, customer_id, amount),
            )
            if not rows:
                # A row with this key already exists. Under read committed,
                # this statement takes a fresh snapshot, so it sees the
                # committed row from the concurrent attempt.
                rows = db.execute(
                    "SELECT id FROM payments WHERE idempotency_key = %s",
                    (idempotency_key,),
                )
            db.commit()
            if rows:
                return int(rows[0][0])
            # Not expected: the conflicting row vanished before we read it.
            # Retry the whole attempt.
        except (
            errors.SerializationFailure,
            errors.DeadlockDetected,
            errors.LockNotAvailable,
            errors.UniqueViolation,
        ) as exc:
            last_error = exc
            db.rollback()
    # Every attempt failed on a transient error. Propagate the error rather
    # than return None, since the function must return an int.
    raise last_error
```

Notes on the choices:

- **Why the unique index is in `migrate`:** rule 1 has to hold under concurrency, and only a database constraint guarantees it. The index creation will fail if the existing data already contains duplicate keys. If that is possible in your data, the duplicates need to be resolved before the migration runs.
- **Why the fallback `SELECT` is safe:** `ON CONFLICT DO NOTHING` waits for a conflicting transaction to finish. If that transaction committed, the insert returns no rows and the `SELECT` finds the committed payment. If it rolled back, our insert succeeds instead.
- **Isolation:** the code uses the default read committed level, so it never depends on repeatable-read or serializable retries.
- I have not run this against PostgreSQL 16. It is based on the documented `ON CONFLICT` and read-committed snapshot semantics.
