This is a write-skew problem. Two doctors in the same shift can each see the other on call and both go off. The fix is to lock the shift row with `SELECT ... FOR UPDATE`, so requests for the same shift run one at a time. Requests for different shifts don't block each other.

- **Fresh data after the lock:** at read committed, the count that follows the lock runs with a new snapshot, so it sees every earlier committed change.
- **Valid requests succeed:** no request needs to retry or fail. Each one waits for the lock, then makes the same decision it would have made if run sequentially.
- **No deadlocks:** each request takes only one lock besides its own doctor row, so lock ordering can't conflict.

```python
def go_off_call(db, doctor_id: int) -> bool:
    db.begin("read committed")
    try:
        rows = db.execute(
            "SELECT shift_id FROM doctors WHERE id = %(d)s",
            {"d": doctor_id},
        )
        if not rows:
            db.rollback()
            return False
        shift_id = rows[0][0]

        # Serialize all requests touching the same shift.
        db.execute(
            "SELECT id FROM shifts WHERE id = %(s)s FOR UPDATE",
            {"s": shift_id},
        )

        # Fresh snapshot (read committed) after the lock is acquired.
        others = db.execute(
            "SELECT count(*) FROM doctors "
            "WHERE shift_id = %(s)s AND on_call AND id <> %(d)s",
            {"s": shift_id, "d": doctor_id},
        )[0][0]

        if others >= 1:
            db.execute(
                "UPDATE doctors SET on_call = false WHERE id = %(d)s",
                {"d": doctor_id},
            )
            db.commit()
            return True

        db.rollback()
        return False
    except Exception:
        try:
            db.rollback()
        except Exception:
            pass
        raise
```
