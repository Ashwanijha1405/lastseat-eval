The race here is write skew. Two doctors in the same shift both see each other on call, both go off call, and the shift is left with nobody. The fix is to make every request for a given shift lock that shift's row first, so requests for the same shift take turns.

Because of that lock, each request counts the on-call doctors only after the previous request for that shift has committed. This works at READ COMMITTED because each statement takes a fresh snapshot after the lock is granted. Requests for different shifts don't block each other.

- **Rule 1 holds:** a doctor is taken off call only if another doctor is still on call at that moment.
- **Rule 2 holds:** concurrent requests for a shift run as if one after another, so any set that would all succeed sequentially also succeeds here.
- **No deadlocks:** each transaction locks only its shift row, then updates its own doctor row.

A short bounded retry loop handles any unexpected transient error.

```python
import psycopg.errors as errors


def go_off_call(db, doctor_id: int) -> bool:
    last_exc = None
    for _ in range(5):
        try:
            db.begin("read committed")
            # Lock this doctor's shift row; serializes all requests within the same shift.
            rows = db.execute(
                "SELECT s.id FROM shifts s JOIN doctors d ON d.shift_id = s.id "
                "WHERE d.id = %s FOR UPDATE OF s",
                (doctor_id,),
            )
            if not rows:
                db.rollback()
                return False
            shift_id = rows[0][0]
            # Fresh snapshot (read committed) taken after the lock was acquired.
            others = db.execute(
                "SELECT count(*) FROM doctors "
                "WHERE shift_id = %s AND on_call AND id <> %s",
                (shift_id, doctor_id),
            )[0][0]
            if others > 0:
                db.execute(
                    "UPDATE doctors SET on_call = false WHERE id = %s",
                    (doctor_id,),
                )
                db.commit()
                return True
            db.rollback()
            return False
        except (errors.SerializationFailure, errors.DeadlockDetected,
                errors.LockNotAvailable) as e:
            last_exc = e
            try:
                db.rollback()
            except Exception:
                pass
    raise last_exc
```
