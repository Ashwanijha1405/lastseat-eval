Each transfer locks both wallet rows in a fixed order (lowest `id` first), then checks the balance and moves the money in a single statement. I haven't run this against a PostgreSQL 16 server.

- **Opposite directions can't deadlock.** Alice→Bob and Bob→Alice both lock the lower `id` first, so neither can hold one row while waiting for the other. Neither is refused; the second simply waits for the first to commit.
- **Balance checks see the latest value.** Under `read committed`, `SELECT ... FOR UPDATE` waits for any other transfer on those rows to finish. It then returns the committed balance, so several transfers out of one wallet are checked one after another. A transfer is only refused (`False`) when the money really isn't there.
- **Totals stay correct.** The debit and credit happen in one `UPDATE` inside one transaction. Money is never created or lost, and the debit carries a `balance >= amount` guard as an extra safety net.
- **Unexpected errors are retried.** A deadlock or serialization failure rolls back and retries, up to 8 times. That stays well under the 60-call limit.

```python
import psycopg.errors as errors

_RETRYABLE = (errors.SerializationFailure, errors.DeadlockDetected)


def transfer(db, from_id: int, to_id: int, amount: int) -> bool:
    for _ in range(8):
        try:
            db.begin("read committed")
            # Lock both rows in a consistent (id) order to prevent deadlocks.
            rows = db.execute(
                "SELECT id, balance FROM accounts "
                "WHERE id IN (%(a)s, %(b)s) ORDER BY id FOR UPDATE",
                {"a": from_id, "b": to_id},
            )
            balances = {r[0]: r[1] for r in rows}
            if balances.get(from_id) is None or balances[from_id] < amount:
                db.rollback()
                return False
            res = db.execute(
                "UPDATE accounts SET balance = balance + CASE WHEN id = %(f)s "
                "THEN -%(amt)s ELSE %(amt)s END "
                "WHERE id IN (%(f)s, %(t)s) "
                "AND (id <> %(f)s OR balance >= %(amt)s) "
                "RETURNING id",
                {"f": from_id, "t": to_id, "amt": amount},
            )
            if len(res) != 2:
                db.rollback()
                return False
            db.commit()
            return True
        except _RETRYABLE:
            try:
                db.rollback()
            except Exception:
                pass
            continue
    return False
```
